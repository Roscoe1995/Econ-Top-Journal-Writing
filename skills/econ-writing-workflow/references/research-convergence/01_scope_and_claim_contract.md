# Scope And Claim Contract

Use this file for full-paper drafting, proposal development, major restructuring, or a project whose question, contribution, terminology, or scope keeps drifting.

Do not load it for local diction cleanup, a narrow paragraph rewrite, citation formatting, or a bounded table-note edit unless the requested change exposes a substantive contradiction that cannot be resolved locally.

## Contents

1. Task-stage gate
2. Scope contract
3. Paper-type spine
4. Draftability decision

## 1. Task-Stage Gate

Classify the task before applying this module:

- `exploration`: keep the question and contribution provisional; do not force premature closure;
- `proposal`: define a testable question and feasible route without presenting planned results as completed;
- `full drafting`: require a recoverable question, contribution structure, evidence/model path, and current non-goals;
- `major revision`: preserve the accepted intellectual core unless the user authorizes reframing;
- `local polish`: skip this module and stay within the requested passage;
- `final audit`: check stability and cross-section consistency without reopening settled choices by default.

Do not expand a local request into a paper-wide audit. If a local edit reveals a high-impact contradiction, report it separately and ask before changing the paper's substantive scope.

## 2. Scope Contract

For `proposal`, `full drafting`, or `major revision`, create a compact author-facing contract:

1. **One-sentence question**: state the phenomenon or relationship, what remains unresolved, and what mechanism, evidence, or measurement the project adds.
2. **Contribution structure**: name one central contribution and any secondary contribution that changes the intellectual claim. Do not erase legitimate theory, data, measurement, structural, or policy contributions merely to force a single-item list.
3. **Must preserve**: record the mechanism, empirical magnitude, data/design feature, scope condition, and secondary contribution that cannot be lost during compression.
4. **Current non-goals**: list mechanisms, agents, policy instruments, extensions, or outcomes that the current version will not attempt.
5. **Terminology and notation**: record the reader-facing term, model or code symbol, intended meaning, and retired alternatives for objects that repeatedly drift.

Keep the contract in a task log, project brief, or revision memo. Never paste it into manuscript prose, table notes, figure notes, appendix notes, or footnotes.

Treat the contract as provisional during exploration. Treat it as frozen only after the user accepts it or the manuscript and evidence make it unambiguous.

## 3. Paper-Type Spine

Use the shortest chain that fits the paper type:

- **Theory**: initial condition or friction -> agent choice -> equilibrium or state transition -> economic result -> testable implication or scope condition.
- **Empirical**: source of variation -> treatment or exposure -> behavioral response -> outcome -> mechanism or scope test.
- **Mixed theory-empirical**: model mechanism -> observable prediction -> measurement -> identifying comparison -> result -> feedback to the mechanism.
- **Descriptive or measurement**: measurement problem -> new data object or measure -> documented fact -> interpretation -> limits of the measure.
- **Structural or quantitative**: economic question -> model object -> identification or calibration -> fit/validation -> counterfactual -> welfare or policy interpretation.

Require each main section to defend one link. Do not force every paper into a causal-treatment template.

## 4. Draftability Decision

- **Ready**: the question, contribution structure, model/design path, and current non-goals are recoverable. Continue drafting.
- **Provisional**: the main direction is usable, but one or more items need a concrete `TODO`. Draft only the unaffected parts.
- **Blocked**: competing definitions or substantive choices would produce materially different papers. Ask the user before selecting among them.

Do not block a bounded rewrite merely because the entire paper lacks a frozen contract. Apply the decision only to the scope of work that depends on the missing choice.

## 5. Reopening Conditions

Reopen only the affected part of the contract when new evidence, a failed identification or model gate, verified close literature, referee/editor feedback, a target-journal change, or an explicit user decision changes the project.

Do not reopen settled content merely to vary style, add complexity, or generate more material. Record what changed, why, and which downstream sections require rechecking.
